## Question

依据 T19 的盘点,决定数据如何变成用户可见的服务(注意平台约束:Vercel、无自有数据库红线是否因数据集破例 —— 若破例要显式记录):

- **托管与查询**:Cloudflare R2 / Supabase / 按年切片静态 JSONL 挂 CDN,三选一(或组合);按出生 key 查询的 API 形态(Next Route Handler 代理 vs 客户端直拉 CDN);
- **自生成 vs 下载数据**:若上游生成脚本可用,是部署时按需生成还是离线预生成为切片;
- **缓存**:与 T17 的 `'use cache'` 矩阵合并(按参数缓存整个命盘页,数据查询自然被吃进缓存);
- **兜底链路**:数据缺录(超出覆盖年份/闰月边界)时回退 T08 本地知识库 + 明示标注;
- **署名落点**:CC BY 4.0 署名在页面的具体形态(钦天监语气)。

## Resolution

2026-11-01 依据 T19 事实(dataset-inventory.md)与用户拍板:

1. **托管与查询:R2 + 偏移索引 + Route Handler 代理**。一次性下载 161MB/77 卷 → 离线预处理(按年切片 + ~19MB key 偏移索引,单查 84KB)→ 上传 Cloudflare R2(零流量费)→ Next Route Handler 代理查询。T19 已证 zstd `--long=27` 无法随机访问、且断语库闭源**不可自生成**,预处理切片是唯一可行路线。"无数据库红线"因数据集破例:R2 为对象存储非数据库,记录在案。
2. **缓存**:并入 T17 矩阵 —— `/chart` 页 `'use cache'` 参数级缓存天然吃掉数据查询,数据层不再单独建缓存;部署即失效。
3. **窗口兜底**:出生在 **1950–2026 之外** → 自动回退 T08 本地知识库解读,页面显著标注「该日期不在数据集覆盖窗口,已切换通用解读」。窗口内闰月等缺录同样走此链路。
4. **双语:zh 全量、en 精简**。zh = 数据集 13 维(窗口内)+ T08 兜底;en = T08 知识库体系(168 条)为主干,13 维不做 en,en 页明示覆盖差异。8.77M 条翻译不现实,先把 zh 做透。
5. **CC BY 4.0 署名双落**:method 页完整声明(链接/许可/修改说明)+ 每个数据集解读区块尾注一行「解读文本改编自 Renhuai123/ziwei-doushu 数据集,CC BY 4.0」。
6. **文案语气风险处置**:数据集文本为上游预写,不逐条改写;展示层以"改编自传统断语体系"框架说明 + 抽样人审把关(不替上游背书具体断言语气),T16 红线 lint 不适用于数据集原文,只适用于自产文案。
