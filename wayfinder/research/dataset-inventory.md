## 2. 自生成能力结论(T20 最关键事实)

**结论:不能自行生成 v4 解读文本;能自行生成命盘结构(与全部 674,976 个合法 key)。**

四重证据:

1. README.md:386(开源边界):断语库不开源,`lib/ziwei/db-analysis.ts` 是占位。
2. `lib/ziwei/db-analysis.ts:54`:`export const STAR_DB: Record<string, unknown> = {};`——13 维论断内容库在仓库里是空集;文件头注释(:1-11)自述"线上完整版…属于核心内容、不随排盘引擎开源"。
3. 生成方式 = "排盘引擎 + 断语库确定性生成,不经 AI"(README.md:131)——引擎开源、断语库闭源,两者缺一即无法复现文本。
4. **MANIFEST.json `engineCommit: "c25dd495 (site repo, 2026-10-15)"`**——数据集生成于上游私有站仓提交,开源仓(HEAD `495b79e`)只是引擎同步快照。另:上游 `scripts/` 仅有 10 个回归测试(`scripts/regression/`),无任何数据集生成脚本;CI(ci.yml)只跑 typecheck + 回归;全仓 grep `zstd|jsonl|csv|parquet` 仅命中 4 个文档文件,零代码命中。

| 能否自生成 | 对象 | 途径 |
|---|---|---|
| ✅ 能 | 任意输入的命盘结构(星曜落宫、四化、格局、大限) | 开源引擎(T02 已定 vendored 路线);可离线枚举 1950–2026 全部 674,976 key |
| ✅ 能 | key 的合法性/枚举/路由 | 引擎 + 历法(`solar-date-exists` 回归保证拒绝不存在日期) |
| ❌ 不能 | 13 维解读文本(passage) | 断语库闭源;唯一途径是下载 Release(全量压缩仅 161.4 MB,单年 ≈2.1 MB) |
| ❌ 不能 | 与 v4 同源的后续更新 | 依赖上游发版;引擎持续更新会导致新引擎输出与数据集有差异(DATASET-LICENSE:53-56 明示) |

**推论**:覆盖窗口被冻结在 1950–2026。**2027 年及以后、1949 年及以前出生的用户没有数据集文本**——T20/T21 必须设计降级路径(引擎排盘 + 无 13 维文本的提示/占位,或仅展示格局库内容)。

## 3. v3.0 样本数据集(Release `v3.0-samples`,2026-05-07)

### 3.1 规格(schema)

- 518,400 条 = 60 年 × 12 月 × 30 日 × 12 时辰 × 2 性别(README.md:179、:186);解读段 6,739,200(每盘同 13 维,每盘 ≈2.1 万字,README.md:24)。**票面"518,382"有误,正确为 518,400**(README.md:186、DATASET-LICENSE:1)。
- 分发格式:**每盘一个 JSON 文件**,文件名 `YYYY-MM-DD-hHH-性别.json`(README.md:200),zip 分 3 卷(实测 1,992,294,400 + 1,992,294,400 + 1,893,639,808 = 5.48 GB,gh release 资产表;README.md:186"压缩 5.5 GB/解压 33.1 GB")。内容 = 完整命盘 JSON + 13 主题解读文本(README.md:188)。
- 字段(README.md:192-200):`birthInfo.year/month/day` 公历 **1924–1983(一个完整甲子)**,每月固定取 1–30 日;`hour` 时辰序号 0–11;`gender` male/female;`longitude` 固定 120(无真太阳时)。
- **票面"CSV vs Parquet"与"天盘/地势/人盘三系标签":仓库内无证据**(全仓 grep `parquet|.csv|天盘|地盘|人盘|地势` 零相关命中;唯一"地势"是 `lib/nihai/tianji.ts:361` 易经卦辞"地势坤",无关)。README/DATASET-LICENSE 均未提及任何三系标签或列式格式;若 Release 内 JSON 另有此类字段,需下载样本验证,但按文档判断不存在。

### 3.2 样本偏差(用作数据源前必读)

1. **合成均匀网格**:按历法网格穷举,非真实人口分布(无出生时辰聚集、无年代人口权重)。
2. **含 2,520 条不存在日期**(2 月 30 日 + 非闰年 2 月 29,105 个日期 × 24),内容与 3 月 1–2 日重复,须过滤(README.md:211 给出过滤条件)。
3. 年份限 1924–1983;经度固定 120° 无真太阳时。
4. 由 v3 引擎 + 当期(旧)断语库生成,与 v4 内容版本不同(README.md:190;DATASET-LICENSE:53)。
5. 与 v4 相比每盘字数少 44%(2.1 万 vs 3.0 万,README.md:24-25)。

### 3.3 "同盘检索"可行性

**不需要 v3 也不需要 v4**:命盘结构是 (y,m,d,h,g) 的确定性函数,开源引擎可离线枚举全网格。同盘(同盘面结构)检索应建在**引擎枚举 + 盘面哈希**之上(如命宫主星集合 + 四化落宫签名),数据集只供 passage 文本。v3 的 51.8 万个散 JSON(33.1 GB)若为检索装载,内存/IO 代价远高于引擎重算——**不推荐把 v3 作为线上服务数据源**;其价值在训练语料与 A/B 基线(README.md:236-241)。

## 6. 体积与切片:三种方案量化对比

基于 MANIFEST/资产表实测数(单年 zst ≈2.10 MB、单年 raw ≈734.8 MB、单盘 ≈83.8 KB):

| 方案 | 对象数 | 单对象大小 | 首次/冷查询代价 | 单 key 查询传输 | 预处理与存储 | 评价 |
|---|---|---|---|---|---|---|
| A · 按年(上游原生,77 个 .jsonl.zst) | 77 | zst 1.92–2.20 MB / raw ~0.72–0.76 GB | 下 1 卷 ≈2.1 MB + 整卷解压 0.73 GB(zstd 长窗口无法随机访问) | 解压后按行索引:一次磁盘读 ≈84 KB;未建索引则全卷扫描 | 全量 161.4 MB 压缩 / 56.6 GB raw;流式逐年处理峰值磁盘 ≈1.6 GB/年 | ✓ 存储与分发单元,首选 |
| B · 按月(自切 924 个) | 924 | zst ≈175 KB / raw ≈61 MB | 下 1 卷 ≈175 KB + 解压 61 MB(≈730 盘) | 同上,月卷内扫描 61 MB | 同总量,对象数 ×12 | ✗ 相对按年无实质收益,徒增对象数 |
| C · 按 key 索引(预处理:解压→逐年 JSONL + key→(offset,len) 索引,或入 SQLite) | 1 索引 + 77 raw 卷 | 索引 674,976 × ~28 B ≈ **19 MB**;SQLite ≈ raw +5–10% | 一次性预处理(全量解压,流式峰值 ≈1.6 GB 磁盘 + 分钟级 CPU) | **精准 84 KB raw**(单行);独立 gzip 后 ≈15–25 KB | 56.6 GB raw 常驻(或 SQLite 单文件) | ✓ 服务层查询方案,配合 A 使用 |

**推荐:T20 采用 A+C 两层**——对象存储/仓库只放 77 个上游年份卷(161.4 MB,含 MANIFEST 的 sha256 做完整性校验与缓存键);部署或首次访问时解压为 raw JSONL 并构建 19 MB 偏移索引(或导入 SQLite),此后 key 查询 O(1) 读 84 KB。不推荐按月(C 无增益)与 per-key 674,976 个小文件(文件数爆炸)。注意压缩比 351:1 只在整卷长窗口下成立,单条独立压缩仅约 3–6:1(84 KB → 15–25 KB),前端传输按此预算。

## 7. 对 T20/T21 的事实提示

1. **文本只能来自下载,不能生成**:服务架构 = 上游 Release(161.4 MB)→ 一次性预处理 → key 查询。预处理管道是 T20 必备组件(zstd `--long=27` 整卷解压不可绕过)。
2. **覆盖硬边界 1950–2026**:窗口外出生(2027+、1949−)无文本,需降级 UX;上游不发新版,窗口不会自己前进。
3. **key 口径 = 未校正时辰**:数据集按裸时辰序号排盘(README.md:148),而 T10 时间链做真太阳时校正——产品必须决策用校正前还是校正后的时辰查数据集(否则查错盘)。建议:排盘展示可用校正后,数据集查询按用户确认的时辰直查,并在 UI 说明口径。
4. **亮度口径差**:v4 文本按"现代修正 v2"生成(README.md:81),我们引擎默认《斗数全书》——文本内亮度字与盘面渲染可能不一致,T22 渲染规格需择一并对齐说明。
5. `ms`(命宫第一主星,15 种值)与 `t`(各维字数)可做轻量路由/摘要预取,无需拉整行 `c`。
6. **同盘检索/同盘名人不需要数据集**:引擎枚举即可(§3.3、§4);T21 的"同盘名人"建议以"同命宫主星/同格局"放宽 + v4 文本仅对覆盖内 8/11 名人可用。
7. v3 不作线上数据源(散 JSON 33.1 GB、旧内容版本、含 2,520 条脏数据);如用作测试 oracle,过滤条件见 README.md:211,并在测试目录加 CC BY 4.0 署名(T02 §5)。
8. 署名落地按 §5.2 的 1+2 组合;免责声明(DATASET-LICENSE:47-50)随尾注呈现。
9. MANIFEST.json 含每年 charts/rawBytes/sha256——直接用作下载校验与缓存失效键,无需自算。
